# Dashboard Module

> Головний дашборд PMS — зведений огляд з основними показниками та алертами.

## Публічне API

Всі публічні функції та типи знаходяться в `api/index.ts`. Імпортуй тільки звідти:

```ts
import { getDashboard, getAlerts } from '@dashboard'
```

| Функція / Тип | Опис |
|---|---|
| `getDashboard()` | Зведена статистика: заїзди/виїзди сьогодні, завантаженість, вільні номери, найближчі бронювання (3 дні) |
| `getAlerts()` | Операційні алерти: прострочені заїзди, неоплачені бронювання, незареєстровані гості, виїзди сьогодні. Автоматично архівує confirmed > 7 днів → `no_show` |

## Залежності

**Модулі** (через публічний API):
- `@core/db` — підключення до БД (`getDb`)

> [!TIP]
> Dashboard — найчистіший модуль проєкту: НУЛЬ legacy-імпортів (`@/lib/*`). Використовуйте як зразок для рефакторингу інших модулів.

## Події

**Емітить** (`events/published.ts`):

```ts
// Dashboard is read-only — no events published
export type DashboardEvents = Record<string, never>;
```

Модуль є read-only і свідомо не емітить жодних подій.

**Слухає:**
Не слухає подій інших модулів.

## Схема даних

Модуль не має власних таблиць. Читає дані з таблиць інших модулів (read-only):

- `reservations` — статистика заїздів, виїздів, завантаженості; автоархівація `no_show`
- `guests` — імена гостей для відображення
- `units` — назви та коди номерів, статус прибирання

## Структура файлів

```
dashboard/
  api/
    index.ts                 ← єдина точка експорту
    dashboard.handlers.ts    ← зведена статистика + найближчі заїзди/виїзди
    alerts.handlers.ts       ← операційні алерти + автоархівація no_show
  events/
    published.ts             ← DashboardEvents = Record<string, never> (свідомо порожній)
  README.md                  ← цей файл
```

> [!NOTE]
> Мінімальний read-only модуль — тільки `api/` та `events/`. Відсутність `domain/`, `data/`, `ui/` — свідомий вибір: модуль лише агрегує дані з інших таблиць.

## Точки розширення

- Додати новий віджет дашборду → розширити `dashboard.handlers.ts` або створити окремий `api/[widget].handlers.ts`
- Додати новий тип алерту → розширити масив `alerts` у `alerts.handlers.ts`
- Винести SQL-запити → створити `data/dashboard.repo.ts` для кращого тестування
- Нова подія → якщо модуль перестане бути read-only, оновити `events/published.ts`
